# Security reporting

Do not put live credentials, private API definitions, personal data or exploitable details in a public issue. Use the repository host's private vulnerability-reporting channel when enabled. Otherwise contact the repository owner privately to arrange a report before disclosing details; this project has not configured a dedicated security address or response SLA.

Include affected versions, a minimal sanitized reproduction and the relevant authentication/destination/serialization behavior. Ordinary diagnostics intentionally omit credentials and bodies; raw response access and custom transports are privileged. Keep generation records private. Providers own API access control, idempotency guarantees, webhook retention, durable processing and sandbox behavior.
