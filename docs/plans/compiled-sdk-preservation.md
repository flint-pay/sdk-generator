# Compiled SDK implementation and preservation inventory

This inventory accompanies [the compiled SDK contract plan](compiled-sdk-contract.md). The baseline is revision `0022e27564b2d446ec8184b08b2fa529dfea9b21`, whose 170 tests passed before migration on Node 24.19.0 and PHP 8.5.10. The frozen source and measurement artifacts are local validation inputs; generated packages and provider source are not checked into this document.

## Ownership and removed duplication

| Decision                                                                                                  | Owner and consumers                                                              | Replaced interpretation                                                                                 |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Exact versus safe integer, decimal representation, format ranges                                          | `codec-plan.ts`; both executors and target declaration/policy compilers          | Numeric representation lists in generation and compatibility; format dispatch during ordinary execution |
| Request/response required keys, readOnly/writeOnly, validation policy, composition traversal instructions | `compileCodec`; runtime descriptors                                              | Both ordinary runtimes' source-schema projection and keyword interpretation                             |
| Public object declarations, dictionaries, optional inherited names, target scalar types                   | `target-types.ts`; target plans and public response guarantees                   | Type derivation in `generate.ts`; lossy response-schema projection in comparison                        |
| Response required-only keys and nested additional-field guarantees                                        | `response-plan.ts`, derived from codecs separately from public declaration facts | `responseValueSchema`, `responseValuesFit`, and `simpleResponseSchema` in generation                    |
| PHP constructors/getters, status/variant identities, known guards, pagination item types                  | `target-plan.ts`; rendering and compiled comparison                              | Renderer-side type/class/variant derivation and comparator reconstruction of PHP identities             |
| Input acceptance, existing-status wire and annotation release rules                                       | `schema-policy.ts`; `comparePolicies`                                            | Raw schema interpretation in the comparison algorithm; public `compareSchemas` is a boundary adapter    |
| Return inclusion and uncertainty                                                                          | `value-guarantee.ts`, `response-compatibility.ts`                                | Boolean shape proof and single-old-alternative conclusions                                              |
| Historical behavior and runtime implementation identity                                                   | Compiled snapshots in generation record version 2                                | Treating today's interpretation of an old source schema as evidence of the old generator's behavior     |

The compiler produces declarative data for the runtime executors. Node and PHP retain their language-specific JSON, exact arithmetic, HTTP, scheduling, inspection, and object primitives. Their descriptor executors are the only value execution paths. Compiler modules have no runtime dependency on the CLI, filesystem, transport, or renderer; AST dependency checks reject forbidden imports and cycles.

Public schema helpers necessarily retain lowering. Node schema-taking helpers also retain caller-owned schema mutation behavior, including model inspection after sensitivity changes and its existing null-only type-array behavior; generated clients use their compiled descriptors. Node uses the same pure compiler module as generation. PHP has an isolated translator in `Internal\SchemaAdapter`, verified against independent serialization fixtures. PHP retains a separate implementation of translation. It has no independent value evaluator, global registry, cache, or ordinary-operation fallback. Its lifetime is tied to preserving the public schema-taking APIs.

## Compatibility and record evidence

The dictionary declaration regression, dictionary required-key loss, and mixed-object nested additional-key loss have independent expected classifications. `compiled-contract.test.mjs` wraps cases through properties, arrays and dictionaries; checks absent bodies versus null, exact-number strings versus ordinary strings, multiple previous results and compatible controls; and verifies stable patch/minor rejection with corresponding major acceptance.

The full existing compatibility suite retains status/default/304/error distinctions, PHP nominal classes and branch positions, target retention, wire policy, pre-1.0/prerelease policy and acknowledged limitations. A proven break is not downgraded by an unresolved comparison.

Version 2 records store compiled snapshots using `shared-json-v1`: a deterministic table of equal JSON subtrees with backward-only references. Storage deduplication preserves the logical semantic representation. Restoration recovers and validates the complete logical plan; raw snapshots remain readable, and unknown encodings, invalid references, cycles and duplicate object keys are rejected. Source provenance is unchanged.

Saved-record tests simulate a historical guarantee absent from identical current source schemas, preserve it over repeated generation, retain legacy provenance/version baselines, report runtime identity changes, compare historical PHP getter/constructor and Node iterator/guard declarations, retain review for unexplained descriptor changes, and reject unknown formats/malformed descriptors without rewriting the record. Source-only `compare` still means analysis under the current compiler. Complex inclusion proofs remain bounded; execution support is not limited by that boundary.

## Measurements and completion checks

Measurements use the same local process/toolchains and synthetic values, with two warmup rounds and the median of five measured rounds. Generation measurements cover in-memory compilation/rendering; filesystem generation and archive installation are separately exercised by the suite. Compressed totals are gzip of concatenated generated contents, a consistent size comparison rather than an npm/Composer archive-size claim.

| Fixture | Compile/render, baseline → compiled | Full fresh generation, baseline → compiled | Private record, baseline → compiled |
| ------- | ----------------------------------- | ------------------------------------------ | ----------------------------------- |
| Library | 0.44 → 0.51 ms                      | 3.02 → 4.73 ms                             | 3.90 → 27.22 kB                     |
| Payment | 1.52 → 3.46 ms                      | 6.59 → 14.21 ms                            | 30.77 → 180.93 kB                   |
| Flint   | 384.60 → 560.96 ms                  | 834.06 → 1666.66 ms                        | 40.15 → 42.27 MB                    |
| Risk    | 64.59 → 105.69 ms                   | 153.34 → 354.47 ms                         | 7.80 → 9.15 MB                      |

Full fresh generation uses one warmup and the median of three runs, including staging, file writes and private record storage. Compiler lookup indexing and shared snapshots resolved the initial repeated-compilation and 150 MB record regressions. Generation still costs more because it compiles and saves historical contracts; this is an explicit generation-time cost.

The 50-object nested exact-number/dictionary decode workload measured 0.109 → 0.100 ms per decode in Node and 0.329 → 0.218 ms in PHP. These measurements describe the local validation workload.

The completion audit checks all requirements in the design plan, the inventory above, superseded paths, saved-plan consumers, public APIs, corruption handling, and package independence. Iterations fixed baseline loss without file changes, missing historical target comparisons, dynamic-schema mutation behavior, shared-lookup cost, snapshot duplication, and a new-method subclass collision. A timing-sensitive existing concurrency test now uses explicit coordination while preserving its out-of-order request assertion.

Validation completed on Node 24.19.0/PHP 8.5.10 and Node 22.16.0/PHP 8.2.33. Both environments passed all 193 tests, TypeScript checks and package dry runs. The generated npm package contents matched across the two environments. Formatting and whitespace checks passed.

The documentation review covered all 13 repository Markdown documents and 49 local links, plus generated package documentation, its six local links and the executable public-helper example. The design document describes the implemented architecture; consumer guides describe public behavior and compatibility limits.

The final completion scan found no remaining items in the implementation and preservation checklist.
